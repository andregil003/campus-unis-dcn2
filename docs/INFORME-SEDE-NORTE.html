1. Arquitectura de Sede Norte

Sede Norte está compuesta por un gateway RB5009 (GW-A), cinco puntos de acceso hAP ax lite (hAP-1A a hAP-5A) formando un anillo OSPF, un servidor institucional (laptop Windows con nginx), y un contenedor Pi-hole para DNS filtrado dentro del GW-A. El enlace inter-sede hacia Sede Sur sale por ether1 hacia SXT-A.

Equipos de Sede Norte:
  • 1× MikroTik RB5009UG+S+IN (GW-A)
  • 5× MikroTik hAP ax lite (hAP-1A a hAP-5A)
  • 1× MikroTik SXT Lite5 (SXT-A, enlace inter-sede)
  • 1× Laptop Windows con nginx (Servidor Norte)
  • 1× Contenedor Pi-hole dentro de GW-A

3. Configuración de GW-A (RB5009UG+S+IN)

Qué hace GW-A

  • Es el gateway de salida a Internet de Sede Norte
    • Router-id de OSPF área 0: 10.10.255.1
  • Anuncia default por OSPF (originate-default=if-installed)
  • Tiene una ruta estática distance=1 hacia el ISP (gana sobre OSPF)
  • Aloja el contenedor Pi-hole (DNS filtrado) en 10.10.254.53
  • Hace NAT (masquerade) hacia la WAN
  • Hace dst-nat del puerto 53 (DNS) a Pi-hole para que ningún cliente se salte el filtrado

Configuración clave

/ip address add address=100.64.1.2/30 interface=ether7 # WAN
/ip address add address=10.10.1.1/30 interface=ether2 # hAP-1A
/ip address add address=10.10.6.2/30 interface=ether3 # hAP-5A
/ip address add address=10.99.0.1/30 interface=ether1 # inter-sede SXT-A
/ip address add address=10.10.255.1/32 interface=lo # loopback router-id
/ip address add address=10.10.254.1/24 interface=veth1 # contenedor
/routing ospf instance add router-id=10.10.255.1 originate-default=if-installed
/routing ospf area add name=backbone
/routing ospf interface-template add interfaces=ether2 type=ptp cost=10
/routing ospf interface-template add interfaces=ether3 type=ptp cost=10
/routing ospf interface-template add interfaces=ether1 type=ptp cost=100
/routing ospf interface-template add interfaces=lo passive
/ip route add distance=1 gateway=100.64.1.1 check-gateway=arp
/ip firewall nat add chain=srcnat action=masquerade out-interface-list=WAN
/ip firewall nat add chain=dstnat action=dst-nat to-addresses=10.10.254.53 protocol=udp dst-port=53
/ip firewall nat add chain=dstnat action=dst-nat to-addresses=10.10.254.53 protocol=tcp dst-port=53
/container add name=pihole interface=veth1 remote-image=pihole/pihole:latest root-dir=/pihole6/root start-on-boot=yes

Verificación en GW-A

/routing ospf neighbor print # 3 Full: hAP-1A, hAP-5A, GW-B
/ip firewall nat print # masquerade + 2 dst-nat DNS
/ip route print where dst-address=0.0.0.0/0 # estática dist=1 + OSPF dist=110
/container print # pihole HEALTHY
/ping 10.20.0.100 count=3 # servidor Sur responde (cruza inter-sede)

4. Configuración de los hAP de Sede Norte (hAP-1A a hAP-5A)

Qué hace cada hAP

  • Forma parte del anillo OSPF punto a punto con el vecino anterior y siguiente
  • Proporciona WiFi a los clientes (SSID UNIS-A1 a UNIS-A5)
  • Actúa como gateway DHCP para los clientes WiFi
  • NO lleva ninguna regla NAT (Regla 8 del enunciado)
  • Anuncia su red WiFi por OSPF como pasiva (no forma vecinos en WiFi)

Configuración clave por hAP (ejemplo hAP-1A)

/ip address add address=10.10.1.2/30 interface=ether1 # hacia GW-A
/ip address add address=10.10.2.1/30 interface=ether2 # hacia hAP-2A
/ip address add address=192.168.1.1/24 interface=br-wifi # WiFi usuarios
/ip address add address=10.10.255.11/32 interface=lo # loopback
/routing ospf instance add router-id=10.10.255.11
/routing ospf interface-template add interfaces=ether1 type=ptp cost=10
/routing ospf interface-template add interfaces=ether2 type=ptp cost=10
/routing ospf interface-template add interfaces=br-wifi passive
/routing ospf interface-template add interfaces=lo passive
/ip dhcp-server add interface=br-wifi address-pool=pool-wifi
/ip dhcp-server network add address=192.168.1.0/24 gateway=192.168.1.1 dns-server=10.10.255.1
/ip firewall filter add chain=input action=drop # DROP final

Verificación en CUALQUIER hAP de Sede Norte

/routing ospf neighbor print # 2 Full
/ip firewall nat print # VACÍO (Regla 8)
/ip route print where dst-address=0.0.0.0/0 # default OSPF distance=110
/interface ethernet print # puertos del anillo en estado R

5. Configuración de Pi-hole — DNS Filtrado (Sede Norte)

Qué es y dónde corre

  • Contenedor Docker dentro de GW-A (RB5009)
  • IP del contenedor: 10.10.254.53
  • Red del contenedor: veth1 (10.10.254.0/24)
  • Estado: HEALTHY
  • Arranque automático: start-on-boot=yes

Cómo funciona el filtrado

  1. El cliente WiFi se conecta a UNIS-A1
  2. DHCP entrega DNS = 10.10.255.1 (loopback de GW-A)
  3. GW-A hace dst-nat del puerto 53 (UDP y TCP) hacia Pi-hole (10.10.254.53)
  4. Pi-hole bloquea dominios en su blacklist y reenvía el resto a upstreams (1.1.1.1, 9.9.9.9)

    7. Prueba de Failover WAN — Sede Norte

    Estado inicial (GW-A)

    /ip route print where dst-address=0.0.0.0/0
    EstadoRuta
    NormalAs 0.0.0.0/0 → 100.64.1.1 (dist=1, ACTIVE)
    WAN caídaDAo 0.0.0.0/0 → 10.99.0.2%ether1 (dist=110, OSPF)

    Pasos de la prueba

    1. Desde GW-A: /ip route print where dst-address=0.0.0.0/0 — verificar que la estática es ACTIVE
    2. Desenchufar el cable de GW-A ether7 (WAN hacia ISP)
    3. Esperar 10-20 segundos
    4. Desde GW-A: /ip route print where dst-address=0.0.0.0/0 — verificar que solo queda OSPF vía 10.99.0.2
    5. Desde laptop: ping 10.20.0.100 — debe responder (tráfico cruzando inter-sede)
    6. Volver a enchufar el cable de GW-A ether7
    7. Esperar 20 segundos
    8. Desde GW-A: verificar que la estática vuelve a ACTIVE

    8. Checklist de Defensa — Sede Norte

    Técnico (verificado)

    • Servidor Norte (nginx, 10.10.0.100, /health = ok)
    • hAP-1A a hAP-5A: 2 vecinos OSPF Full cada uno
    • GW-A: 3 vecinos OSPF Full (hAP-1A, hAP-5A, GW-B)
    • NAT vacío en todos los hAP de Sede Norte
    • Failover WAN Sede Norte verificado
    • Restauración WAN Sede Norte verificada
    • Pi-hole DNS filtrado funcionando
    • DNS forzado con 8.8.8.8 (dst-nat)
    • Netwatch conntrack limpieza configurado en GW-A

    Documentación (entregable)

    • Documento de ≤2 páginas (decisiones + problemas)
    • 05-RESPONSABLES.md con nombres reales

    Instalación física (+5 puntos)

    • Rackeo: GW-A y hAPs en rack o estructura ordenada
    • Etiquetado: ORIGEN / PUERTO → DESTINO / PUERTO
    • Organización: velcro/bridas, sin cables colgando
